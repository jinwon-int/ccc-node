- **External wait (#2728): a detached-job wait no longer calls an unfired timer or a `--user` unit lost.** The bridge probed only the system `<unit>.service`, so a job that a transient `.timer` starts later (service inactive until it fires) and a `systemd-run --user` unit (invisible to the system manager) were reported `Detached job lost (no EXIT marker)` — at the first poll when the log did not exist yet, after 15 minutes when it did — while the job was fine; `lost` is never resumed, so the real `EXIT=` then reached nobody. `external_wait_cli register --source detached-job` takes `--scope system|user` (default `system`) and `--scheduled-at <when>`; the wait record stores them as `scope` / `scheduled_at` (the hooks-side registry's names, only when set), the monitor asks `systemctl --user` for a user unit and treats an armed `<unit>.timer` as "not started yet", and the registration baseline (#2740) uses the same probe. `detached_jobs.py register --user` passes `--scope user` to the wait it arms. `lost` is now confirmed by a second probe 2 s later, so a timer handing over to its service or one slow `systemctl` answer does not end the wait. Records without the new fields are probed with the same `systemctl is-active <unit>.service` call and judged as before; a timer that is gone with no marker is still `lost`. Registering an open wait again with `--scope` / `--scheduled-at` updates it. The wait budget and notify-only downgrade (#2636) and the non-systemd path are unchanged.
