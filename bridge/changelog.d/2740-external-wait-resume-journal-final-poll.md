- **external-wait: a restart during the continuation turn no longer replays it, and a GitHub wait reads its result once more before expiring (#2740).** (1) The Telegram resumer runs a whole agent turn, and the wake was journaled `done` only after that turn returned, so a bridge restart mid-turn left it `pending` and the next process sent the same notice and ran the same continuation again. The monitor now journals `wake.state = "resuming"` (`ExternalWaitRegistry.mark_resume_started`, a compare-and-set from `pending`) after the notice lands and before the resumer is awaited; `reconcile_on_start` closes a leftover `resuming` wake as `done` with `resumed=false` and `skip_reason=resume_interrupted`, so it is a dropped promise (SessionStart, `external_wait_cli list`/`ack`) instead of a second run. `acknowledge` treats `resuming` like `pending`. Matrix/Hande resumers only enqueue and behave as before. The monitor loop still awaits the Telegram turn; only the duplicate run is fixed here. (2) A PR-checks, merge-queue or Actions-run wait at its deadline was expired before GitHub was asked, so a node that came back (or a loop held up by a long turn) after the deadline missed a result that had arrived meanwhile. The deadline poll now reads GitHub once and a terminal answer ends the wait as usual (and may resume); still pending or a read error expires it as before.
