- **A Cloudflare 403 block page is now a transient failure, retried once (#2808).** On 2026-11-13 three nodes failed Claude turns within 30 minutes on `Failed to authenticate. API Error: 403 Attention Required! | Cloudflare`; the bridge logged `retryable=False`, so an automatic follow-up turn (CI/merge-queue wake) ended without an answer although the next turn minutes later succeeded. `sdk_text.is_edge_block_message` matches only a 403 carrying the block page — a plain 403 keeps the old non-retryable path. The Claude runtime now marks that event `retryable=True`, and a turn that failed this way **before producing any answer text, interim text, or tool call** gets the existing bounded retry (`CCC_TURN_ADMISSION_RETRIES`, default 1) after a 30 s pause, under the new `failure_class="edge-block"`. A turn that already reached a tool is never replayed. The user-facing failure line says `❌ Processing failed (temporary edge block): …`. `TurnEventState.tool_started` records whether any tool started in the turn.
