- **Audience-routed distill jobs are closed, not stranded, after a memory-mode switch (#2333).** After a node switches `CCC_BRIDGE_MEMORY_MODE` from `audience-scoped` to `off`/`curated`, audience-routed jobs left at `local_sink_status=pending` (or `retryable_failed`) were never claimed again. The node-global local sink still never adopts them — audience content may belong to a non-owner audience and the global memory is the owner's own — but now closes them as superseded, writing nothing to the global or any audience store. The state is stored rollback-safe with no new status value: `local_sink_status=terminal_failed` plus `error_code=local_sink_superseded_route`, so an older bridge reached by a self-update rollback parses it as plain terminal work instead of failing every `list_jobs()`/`recover_stale_running()` sweep. Only the status, `error_code` and `updated_at` change; extraction output, route and attempt counters are kept, and Wiki-sink writes no longer erase the marker. Switching back to `audience-scoped` makes exactly these marked jobs claimable again like `pending` (attempt counter preserved), so each is written to its original audience once; other terminal failures are never resumed. Superseded jobs age out under journal retention like `done`/`unroutable`, but are exempt while audience routes exist. With no node-global sink composed (privacy gate), routed work stays `pending` as before.
