- **hande (#2764): agent files and images go to the 「한데」 room as `attachment` frames.** Contract: family-messenger `docs/FLEET-WORKER.md` "나가는 첨부 — `attachment` 출력 프레임" (#761/#762), the mirror of the inbound attachment turn (#2606). With the new `attachment_out_frames` knob on (default `false`; it reuses `attachment_spool_dir`, now required by either attachment knob), the files a final answer names are chosen by the same rule Telegram and Matrix use for auto-send (`core/deliverables.py`: deliverable extension, real file under 50 MiB, inside `PROJECT_ROOT`, direct rooms only), at most 4 per turn (the bot's limit). Each is re-read with the Matrix `read_deliverable` checks and written into the spool as `out-<32 hex>.bin` (`O_CREAT|O_EXCL|O_NOFOLLOW`, fsync; 0600 when the bridge owns the spool, else 0640 in the spool directory's group; an *other*-writable spool is refused), then announced in an `attachment` frame (`v`, `path`, `kind`, sniffed `mime`, `name` unless it has bidi controls, `size`, plaintext `sha256`) **before** `result`. The bridge waits up to 60 s per file for the bot's new `attachment_ack`/`attachment_nack` answers (an older bot that never answers costs one window, not one per file); a nack, a timeout or a local failure appends `📎 첨부를 보내지 못했습니다: <name>(<reason|no_ack>)` to the answer — never a path. Files outside the project root are not sent (the hande port has no confirm step) and the answer says how many were skipped. Leftover `out-*.bin` files of its own are deleted 30 s after `result` and when the bot hangs up. Knob off: no frame, paths stay text, exactly as before. Rollout order: the bot's `NATIVE_MLS_BOT_AGENT_ATTACHMENTS_OUT` first, then this knob. `health_signals()` reports `attachment_out_frames`, `attachments_out_sent`, `attachments_out_acked` and `attachments_out_failed`.
