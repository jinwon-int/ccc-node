- **⏳ status line now covers the session's own background work (#2605, the #2081 §3 follow-up).** The bridge already tracked each Claude session's run-in-background Bash tasks body-free (#2291/#2305) but only used it for session protection; the per-conversation status message showed registered GitHub waits alone, so a turn that left a 15-minute background job behind looked finished. Layer 1 — automatic, no agent action: after the reply, a route whose live session still owns background tasks gets `⏳ Running in background · N background tasks (since HH:MM; resumes automatically when done)` on the same status message (Telegram, Matrix and hande); when the task's terminal frame arrives the handler refreshes the line to `✅ background task finished → continuing (HH:MM)`, which expires like any other finished line. Counts and clock times only — never a command or output body. Layer 2 — optional label: `external_wait_cli register --source local-task --task-id <harness task id> --summary "…"` names one of those tasks on the line; the record is never polled, is closed from the task's own terminal frame (no second wake — the harness is already continuing the session), expires without a wake at its deadline (`⏰ background task watch expired`), and is closed as `lost` on bridge restart. Sessions without the seam (Codex) are unchanged; every new path is fail-open.
