- A user turn submitted while the Claude CLI was running an autonomous turn (a run-in-background `<task-notification>` continuation) no longer waits forever for a terminal frame when the CLI merges that prompt into the running turn and emits one `ResultMessage` for both (#2440; jingun 2026-10-21 10:26 KST: the request stayed `occupied` for 2 h+ while every later message got the busy notice and the stall probe reported `liveness unknown`). The terminal frame is now parked for `CCC_CLAUDE_MERGED_TURN_GRACE_SECONDS` (default 20, clamped 1–300): a turn-bearing frame within the grace means the CLI ran the user turn separately, so the parked result is delivered on the autonomous route exactly as before and the new frame goes to the user turn; no frame within the grace means the CLI coalesced them, so the parked result completes the user turn (its text arrives as the reply to that message). A parked result whose waiter has already given up, or whose reader died, is still delivered on the autonomous route rather than dropped; closing the session cancels the park before failing the turn. The autonomous-turn lifecycle "end" is announced when the window closes, before the park.
