- **Bridge empties its own unit cgroup before exiting (#2646).** On stop, systemd 255's `KillMode=mixed` final SIGKILL walks `cgroup.procs` one `pidfd_open` at a time, skips only `ESRCH`, and aborts on anything else; the kernel returns `EINVAL` for a reaped session/process-group leader whose members still live — an in-flight Claude Code tool shell during teardown. systemd then logs `Failed to kill control group …, ignoring: Invalid argument`, does not wait for the cgroup to empty, and the next start reuses it (`Found left-over process …`), so old-generation tool processes overlap the new bridge and memory counters span restarts (#2633; 8 of 10 nodes, 263 survivors in one week). `main()` now ends with `sweep_own_unit_cgroup()` (`bridge/utils/unit_cgroup_sweep.py`): it SIGKILLs every other PID in its own cgroup with plain `kill(2)` and repeats until only itself is left (3 s deadline, fail-open). It runs only for the main process of a `ccc-*bridge*.service` unit — cgroup v2 leaf name, `INVOCATION_ID`, and a `systemd` parent are all required, so a test run or tool shell inside a bridge cgroup never sweeps the live bridge. Opt out with `CCC_BRIDGE_EXIT_CGROUP_SWEEP=0`.
