- **external-wait: a short outage no longer uses up a wake, a wake that gives up is a visible dropped promise, and a detached wait ignores the marker an earlier run left in the log (#2740).** (1) The monitor drained every pending wake on every 5 s tick, so the ten delivery attempts were spent in under a minute and a one-minute Telegram/network outage ended the wake `failed`. A failed attempt now schedules the next one with a growing delay (5 s doubling to a 15 min cap, `wake.next_attempt_epoch`; `ExternalWaitRegistry.due_wakes`), so the ten attempts span about 36 minutes; a bridge restart retries at once. (2) Nothing read `wake.state == "failed"` — no notice, no continuation, no SessionStart row, pruned after 24 h. Giving up now records `resumed=false` and `skip_reason=notify_failed` (an existing reason is kept), `dropped_promises()` returns it, and `external_wait_cli ack` closes it. (3) A `detached-job` wait took any `EXIT=` line in the log's last 8 KiB as the result, so re-running a unit with the same appended log ended the new wait on the previous run's exit code within seconds. Registration now records `log_offset` — the log size, when the log already holds a marker while the unit is running — and the monitor reads only what was written after it (a log shorter than the offset is read whole). `external_wait_cli register --source detached-job` measures it or takes `--log-offset`. A job that finished before it was registered (unit not running) is accepted as before.
