- **node_status (#2771): a Telegram-retired node is judged by its declared frontends.** `node_status` (CLI / family-ops MCP) read the `service` section only from the Telegram `start.sh --status` text, so every node whose frontend list (#2342: `CCC_FRONTENDS`, else `$HOME/.claude/frontends`) leaves out `telegram` was reported `healthy: false` / `dead (no PID file)` even with a healthy Matrix or 「한데」 bridge. On such a node the section now reports `telegram: "retired (frontend list)"`, adds `telegram_drift: "retired but running"` when the retired bridge is alive again (the ccc-doctor rule), and fills `frontends.<name>` from each declared frontend's body-free `<bridge home>/.ccc-<matrix|hande>/health.json` (`service`/`claude`/`agent` state, `pid`, `age_seconds`, `stale` after 300 s). `healthy` is `true` only when every declared frontend is `available`/`healthy` and fresh, `false` when one is stale or down, and `"unknown"` when a health source is missing or unparseable. Nodes without a frontend list, or that still declare `telegram`, get the same output as before.
