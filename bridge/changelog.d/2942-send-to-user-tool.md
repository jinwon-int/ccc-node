- **feat(bridge): `send_to_user` tool for verbatim mid-turn delivery (#2942).** On Claude Fable 5.x / Mythos 5.x / Opus 5.5, text the model writes between tool calls comes back as a progress-update `thinking` block once it is longer than a sentence or two, and that block is a short summary (#2161 posts it as the interim bubble). A body the owner had to receive as written — text to paste elsewhere — arrived as two or three lines (measured on a hande node: 5 of 15 mid-turn bubbles, the same body three times in a row); the original text is not returned by the API. Tool inputs are never summarized, so the bridge can now give the model one tool, `mcp__bridge__send_to_user(message)` (`core/send_to_user.py`, an in-process SDK MCP server): the message is posted into the room of the turn being served through the interim path, unchanged apart from ANSI/control characters, and the tool result reports the outcome (`bytes`, `interims_left`) or an error with nothing sent (`too_long`, `interim_limit`, `interim_frames_off`, `no_active_turn`, `send_failed`) — never a silent cut or drop. No room argument and no per-call approval: the destination is the final answer's. Opt-in per frontend config (`send_to_user_tool`, default off; hande: needs `interim_frames`), Claude provider only. A provider session only gets the tool from its first turn — the session record keeps the id it was declared for (`send_to_user_session`) — because adding a tool mid-session invalidates the session's earlier thinking blocks; switching the knob on takes effect with each room's next new session.
