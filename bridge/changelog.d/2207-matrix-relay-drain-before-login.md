- **Matrix frontend: in fleet-relay mode the push spool drains before — and without — the Matrix session (#2207).** The spool notifier used to start only after `transport.open()`, so on a node whose DNS was down (three reboots across the fleet) the homeserver lookup failed first, the process crash-looped, and the Telegram bridge's own `telegram_init_retry_loop` alerts sat in the spool for 48 min / 10 h although the relay is reachable by tailnet IP. With `CCC_PUSH_FLEET_RELAY_URL` set the notifier now starts ahead of the transport (relay delivery never touches Matrix; `MatrixSpoolNotifier` accepts `transport=None`), and when the open fails the process waits up to `CCC_PUSH_FLEET_RELAY_EXIT_DRAIN` seconds (default 15, 0 = off) for the spool to empty before re-raising. A relay notifier started early is not registered a second time as a task-group leg; room mode (no relay URL) is unchanged.
