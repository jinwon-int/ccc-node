- **Bridge memory guard: per-node limits survive `install` and `memory-guard` reruns (#2633).** Per-node `MemoryHigh`/`MemoryMax` values (#2545) live only in the generated `10-ccc-memory-guard.conf`, and a rerun without `CCC_BRIDGE_MEMORY_HIGH/MAX` silently rewrote them to the 50%/75% defaults. Each unset value is now taken from the existing ccc-generated drop-in (marker-checked; hand-written, symlinked or unparseable values are not carried over), then the default; an explicit env value still wins and `50%`/`75%` passed explicitly resets a node. The run prints `keeping the existing memory guard value(s): …`. Ordering is validated on the merged values before anything is written.
