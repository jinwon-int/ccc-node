- **mkdir token-lock fallback no longer reclaims a claim that was replaced while it waited (#2738).** In the last-resort tier (no `flock`, no `python3`), a contender that lost its first `mkdir` to a dead holder's claim waited one second and then reclaimed whenever the pid file still named a dead process. If another reclaimer removed the stale dir and a late claimant created a fresh one but had not written its pid yet, the waiting contender deleted that fresh claim and both started (seen once in a 26.04 merge-group run of `start-lib.test.sh`). `acquire_token_lock` now records the claim dir's identity (inode + ctime via `find -printf`) before the wait and refuses if it changed; an unknown identity keeps the old behaviour. `start-lib.test.sh` reproduces the interleaving deterministically with a `sleep` stub, checks that an unchanged stale claim is still reclaimed, and prints the winners and pid file when a race count is off.
