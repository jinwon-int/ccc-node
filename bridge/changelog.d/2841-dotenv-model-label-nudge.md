- **`CCC_MODEL_LABEL`, `CCC_CRUSH_MODEL` and the webhook nudge bind settings honour the bridge `.env` too (#2841 follow-up).** After #2842 the `env_int`/`env_flag` switches read the `.env` layers, but three readers still looked at `os.environ` only, so on Hande / Matrix units (which never go through `start.sh`'s export) a value written only to `.env` was ignored: the session banner's `◆ Model:` label (`core/turn_notices.py`), and the nudge listener's `CCC_WEBHOOK_NUDGE_ENABLED` / `_HOST` / `_PORT` / `_MAX_BODY_BYTES` plus Matrix's `CCC_MATRIX_WEBHOOK_NUDGE_PORT` (`core/webhook_nudge.py`, `core/matrix/lifecycle.py`). They now read the process environment first and then the installed `.env` fallback (`dotenv_fallback.lookup` / new `merged_environ`). `CCC_WEBHOOK_NUDGE_SECRET` is a credential name and never in that fallback, so the listener still needs it in the process environment and stays fail-closed (logged) without it; an explicit `environ=` mapping is read as given. `CCC_CODEX_REAL_CLI_PATH` needed no change: the #1771 wrapper hand-off already gives the wrapper child and the startup preflight the `.env` value. Takes effect only after the bridge is redeployed.
