# 이어하기 큐(yield-and-continue) 에이전트 사용 계약 (#1113)

한 턴에 다 못하는 작업을 이어갈 때는 **묶음을 등록하고 턴을 정상 종료**한다.
브리지가 대화가 놀고 있음을 확인하면 등록된 묶음을 새 자율 턴으로 시작한다.
한 개의 몇 시간짜리 턴 대신 묶음 단위 바톤터치로 마라톤이 계속된다 — 묶음
사이에 보고가 발신되고, 사용자 메시지가 끼어들 수 있고, `/stop`이 묶음
경계에서 동작한다.

## 에이전트가 할 일

다음 묶음이 남아 있으면 턴을 끝내기 전에:

```bash
python -m telegram_bot.core.continuation_cli register \
    --prompt "<다음 묶음: 무엇을, 어디서부터, 어떤 산출물까지>"
```

그리고 **턴을 정상 종료**한다. 등록만 하고 턴을 붙잡고 있으면 브리지는
"활성 턴 있음"으로 보아 시작하지 않는다. 자연어로 "이어가겠다"고 말하는
것은 등록이 아니다 — `continuation_id`를 받아야 큐에 들어간 것이다.

- **(user, chat)당 pending 1건**: 같은 턴에서 두 번 등록하면 새 것이 옛
  pending을 대체한다(실행 중인 레코드는 현재 턴 자신이라 건드리지 않는다).
- 프롬프트는 4,000자까지. 다음 턴이 기억 없이 바로 이어갈 수 있게
  위치·결정·남은 일을 자기완결적으로 적는다.
- 등록은 활성 턴 경로(active-turn route)에 fail-closed로 묶인다: 경로가
  없거나 모호하면 exit 3 — 이때는 현재 턴에서 계속하거나 자동 이어하기
  불가를 사용자에게 알린다.

## 브리지가 하는 일

- 활성 턴 없음 + pending 있음 → `usage_mode=MODE_AUTONOMOUS`의 새 턴으로
  시작한다. 프롬프트는 `[external_event: continuation_queue id=...]`
  origin이다(사용자 발언 아님).
- 턴 결과는 분할 발신 경로(#1109)로 대화에 전달된다.
- **이중 시작 방지**: 경로 파일이 모호·판독 불가면 시작하지 않고, 프로세스
  세션 레지스트리가 최종 하드 가드다(레이스에서 진 쪽은 시작 실패로 끝난다).

## 가드레일 (진행 제한이 아니라 방호)

| 장치 | 동작 | 해제 |
|---|---|---|
| 일일 트립와이어 `CCC_CONTINUATION_DAILY_CAP`(기본 20) | 도달 시 묶음은 `cap-hold`로 보관 + 알림 | 사용자가 `/continue` |
| 연속 실패 3회 | 체인 중지 + 알림, 묶음은 `cap-hold`로 보관(유실 아님) | `/continue`로 재시도, `/stop`으로 폐기 |
| 사용자 `/stop` | pending·cap-hold·실행 중 묶음까지 취소 | — (사용자 의사 최우선) |

## 운영

- `CCC_CONTINUATION_ENABLED`(기본 **off**)로 모니터를 켠다. 끄면 큐는
  기록만 되고 자동 시작은 일어나지 않는다.
- 이어하기 턴은 자율 토큰을 소비한다(usage-meter의 autonomous로 계량).
- 사용자 확인: `/continue`(cap 해제), 조회는 CLI `list`, 취소는 CLI
  `cancel <continuation_id>` 또는 `/stop`.
