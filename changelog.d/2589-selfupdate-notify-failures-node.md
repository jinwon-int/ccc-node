- `scripts/ccc-self-update.sh` (#2589): `~/.claude/self-update.notify` = `none` no longer swallows failures. A node opted out with `none` suppressed every notice, so five consecutive `prepare-failed rc=3` ticks (2026-10-22..26) reached nobody. `none`/`off` and the new explicit `failures` now mute only the two success notices (update completed `ok-*`, pending activation reconciled `reconciled-*`); every failure, stall, warning, recovery and incomplete activation is still pushed and logged as `notify=pushed mode=<mode> class=alert`. The class is fixed at each call site (`notify` defaults to `alert`), never read from message text. A deliberate full mute is the new `silent` mode, which suppresses alerts too and logs `notify=warning mode=silent` plus a stderr warning on every run. Every suppression still logs `notify=suppressed reason=operator-notify-<mode> dedup=… class=<class>`, and `status` prints the effective mode.
- `scripts/ccc-self-update.sh` (#2589): the `SelfUpdate` record's `node` is resolved as `CCC_NODE` → `$STATE_DIR/node.txt` (#2541) → `hostname -s`, the order the other fleet scripts use. `localhost` and empty values are never used, so Termux nodes stop arriving as `node:"localhost"`; with no real source the record says `unknown-node` and the run logs `notify node=unknown-node reason=no-node-identity` and warns on stderr.
