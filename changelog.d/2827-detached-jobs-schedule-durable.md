- **Detached jobs (#2827 proposal A): `schedule --durable` makes a scheduled job survive a reboot.** It writes the job as a persistent `<unit>.service` + `<unit>.timer` pair (`Persistent=true`) instead of a transient timer, enables the timer, and the wrapper disables it and deletes both files after the run; a run missed while the node was down fires once at the next boot. One-shot only (`--at` must be an absolute future instant), never overwrites an existing unit file, and rolls back what it wrote when `daemon-reload`/`enable` fails. `export-timers` marks such rows `durable` and `restore-timers` never replays them. `ExecStart=` escapes systemd's `$`/`%` expansions so the wrapper's `$rc` reaches bash. Writing unit files is a node configuration change and needs the same approval as a hand-written persistent unit; `--print` shows the files without writing.
