- **The skills-intake review and revise handlers isolate a `claude` reviewer from the worker account's context (#2491, a2a-nexus#2422 follow-up).** Before, `claude -p` loaded the worker account's `~/.claude/CLAUDE.md`, its SessionStart/Stop hooks (node memory and Wiki prefetch injection, the evidence/notify Stop hooks) and its user MCP servers. That context sat in the same session as the untrusted candidate skill, and the session ran in the worker root. When the agent basename is `claude`, including the default when `REVIEW_AGENT_BIN` is unset, both handlers now add `--setting-sources ""` and `--strict-mcp-config` after the operator args. Each is passed as a separate argv element, so the empty value survives. The reviewer also now runs from an empty private directory inside the handler's temp dir. An operator `--setting-sources` or `--strict-mcp-config` in `REVIEW_AGENT_ARGS` takes precedence and is not duplicated. The new opt-in `SKILLS_INTAKE_CLAUDE_SETTING_SOURCES=user` keeps only the `user` source. `project` and `local` are always dropped, and an unknown name means the setting is ignored. Other agents (pi/piri, the danso wrapper) keep their exact argv and their inherited cwd. The tool-lock check still judges only the operator's tokens.
