- **Termux DNS health watch (#2937).** New opt-in `scripts/termux-dns-health-watch.sh` (installer `scripts/install-termux-dns-health-watch-cron.sh`, marker `# ccc-node:dns-health-watch`, default `2-59/5 * * * *`) detects the Android system resolver failing while a raw UDP query to a public resolver works — the 2026-11-28 incident where the Tailscale Android app's in-VPN DNS (`100.100.100.100`) stalled after a network blip and every app's name lookup failed for ~5 hours (reconnecting Wi-Fi did not help; toggling the Tailscale connection did; upstream tailscale/tailscale#22273). After `CCC_DNS_WATCH_THRESHOLD` (default 2) consecutive broken runs it pushes one `dns-health` `notice` record to the push spool, and one on recovery; a fully offline node is only logged. Detect + alert only — it never reconnects the VPN. State and per-run log live under `CCC_STATE_DIR` (`dns-health-watch.json`, `dns-health-watch.log`); exit codes 0 ok / 1 broken / 3 offline. Registered in the doctor cron-marker registry and the shared gen-stamp lib.
