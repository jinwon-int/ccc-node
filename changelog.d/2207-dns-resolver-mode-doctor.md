- **`ccc-doctor` now warns before a reboot turns a node's DNS into SERVFAIL (#2207).** Twice on dungae and once on jingun a reboot left tailscaled with no upstream resolver (`no upstream resolvers set, returning SERVFAIL`): the Telegram bridge looped in `initialize()` for 48 min / 10 h, Matrix crash-looped, and both alert channels sat inside the same outage. The trigger is a tailscale-written `/etc/resolv.conf` that lists only MagicDNS, which makes tailscaled start in `direct`/`openresolv` mode and snapshot itself as the system resolver. Three read-only rows: `dns resolver mode` (경고 on that shape, 정상 on the systemd-resolved stub symlink, 해당 없음 without tailscale state), `dns upstream` (resolved must know an upstream besides `100.100.100.100`) and `dns resolution` (one bounded `getent hosts api.telegram.org`; `CCC_DOCTOR_DNS_PROBE_HOST=` disables it). Nothing is auto-fixed; the action text names the per-node remedy (stub symlink + `resolved.conf.d/10-upstream.conf` + tailscaled restart). Test seams: `CCC_DOCTOR_RESOLV_CONF`, `CCC_DOCTOR_TAILSCALE_STATE`, `CCC_DOCTOR_RESOLVECTL_BIN`, `CCC_DOCTOR_GETENT_BIN`.
