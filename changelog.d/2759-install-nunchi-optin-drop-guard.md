- **`install-nunchi.sh --apply` refuses to silently drop an opt-in the node already had (#2759).** On 2026-10-25 two nodes were re-applied with only a provider flag while their install record said `--judge-apply`. The installer rewrote its managed cron lines without the judge line and overwrote the record, so every later self-update replay kept the reduced flags; it went unnoticed for 17 days. `--apply` now compares the previous `state/install-nunchi.json` with the opt-ins the new invocation resolves to (flags and `CCC_NUNCHI_*` environment) before its first write. If `--judge`, `--judge-apply`, `--wiki-promote`, `--wiki-promote-apply`, `--conflict-sweep`, `--verbatim-backend`, `--audience-scoped`, `--gotgan-run-bytes` or `--gotgan-python` would be lost it exits 5 with the crontab, record, hook settings and mode untouched, and prints the dropped opt-ins and the command that keeps them. `--judge` after a recorded `--judge-apply` counts as a drop of apply mode, `--judge-apply` covers a recorded `--judge` (same for `--wiki-promote[-apply]`), and a different value for a valued flag is an explicit choice. `--keep-optins` carries every recorded opt-in forward; `--allow-drop-optins` acknowledges the drop. Without `--apply` the same warning is printed and status runs as before; a bare status call stays quiet. Replaying the record (self-update) is never refused, a missing or malformed record blocks nothing, and `--remove` is not guarded. `install-termux-mempalace.sh`, which re-applied nunchi as `--apply --<provider>`, now passes `--keep-optins`.
