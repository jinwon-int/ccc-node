- **`ccc-self-update.sh` now refreshes drifted installed A2A handler copies on up-to-date ticks too (#1460).** The #2357 refresh ran only on a tick that changed the checkout, but the tick that first pulls a commit runs the previously installed script — so the tick that first pulled #2357 had no refresh step, every later tick was up-to-date, and two fleet nodes kept drifted reviser/reviewer handler copies behind a current checkout until main changed again. The same idempotent step (only `cmp`s existing copies, reinstalls on drift alone, never fresh-installs, restarts nothing, honors `CCC_SELF_UPDATE_A2A_HANDLERS=0`, skips a not-writable destination with one log line) now also runs on settled up-to-date exits: `done result=up-to-date` (with or without a healthy runtime probe), a successful recovery restart, and a reconciled pending activation. Refusing or deferred ticks (pending-activation unsafe/incomplete, failed recovery, worktree gate, wrong branch, dirty tree, lock/busy) never run it.
- `a2a-handlers` log lines keep their shape and gain a trailing `tick=changed|up-to-date` field. A refresh failure is notified once per checkout SHA (dedup key `a2a-handlers-fail-<sha>`, remembered in `~/.claude/state/self-update.a2a-handlers-notified`); repeat up-to-date ticks log `a2a-handlers notify=suppressed reason=already-notified` instead, and a clean pass clears the marker.
