- **Harness single-run locks no longer rely on `mkdir(1)` being exclusive (#2749).** Ubuntu 26.04's uutils `mkdir` 0.10.0 let several concurrent creators of one path all succeed (11 of 200 rounds of 20 creators on a GitHub runner; GNU `mkdir` and bash noclobber 0 of 200 — the root cause behind #2738/#2745). The three remaining `mkdir` locks now use an exclusive create through bash noclobber (`O_CREAT|O_EXCL`, a builtin): the `refresh-memory.sh` flock-less fallback (`.refresh.lock.d`, still logged as `flock unavailable; using mkdir fallback`), the `skill-review/autoinstall.sh` single-runner lock shared by the sweep and the incremental create (`.autoinstall.lock`), and the `resource-pressure-guard.sh` run lock (the pid now lives in the lock file). Paths, stale windows (30 min / 5 min / dead pid) and skip behaviour are unchanged; a directory lock left by an older version blocks or is reclaimed exactly as before. Each suite gains a case where a `mkdir` that always reports success for the lock path must not let a second run through; those cases fail against the old code.
