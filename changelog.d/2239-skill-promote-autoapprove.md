- **Mechanical fleet-skills promote PRs can be approved by the publisher's own sweep under an owner-switched standing approval — default OFF, dry-run first (#2239, lane L3).** `auto-merge` marked promote PRs ready and tried to squash-merge them, but nothing approved them, so branch protection (1 approval) held every batch for a hand-run relay approval. A new tri-state `CCC_SKILL_PROMOTION_AUTO_APPROVE` / owner `0600` flag file `skill-promotion.auto-approve` (`off` default | `dry-run` | `true`; an unsafe or garbage flag file reads as off) adds a gated approval step to `_sweep_promote_merge` for rows with no creation-time identity hits, green checks and `MERGEABLE`. The sweep fetches the full `gh pr diff` (bracketed by two reads of the same `headRefOid`), requires every changed path to sit under `approved/<audience>/<staged skill>/` (new ledger field `staged_names`; binary, symlink, submodule and unparseable entries block), rescans every added line of every file with the intake scanner and the fleet-identity scan (`approval.json` gets an exact-shape check bound to the batch's reviewed trees), and on any hit reports `needs-human-autoapprove-blocked` with reason codes only, then continues today's flow. `dry-run` records `would-approve-promote-pr` and one `a2a-promote-autoapprove` ledger row per head; `true` runs `approve-via-relay.sh --review-profile P --repo R --pr N --expected-head HEAD --operator-approved --ssh-target T` with `CCC_EXPLICIT_USER_APPROVAL=1`, records `{mode: "approved", profile}`, and enqueues with `gh pr merge --squash --match-head-commit HEAD` (no `--delete-branch` — gh refuses it on fleet-skills' merge queue and the repo deletes merged heads itself; never `--admin`) → `promote-pr-merge-requested`, with the terminal state recorded by the next sweep's live read. A relay failure is `approve-failed` (exit code, ledger row, at most 3 attempts per head) and falls back to today's merge attempt; a PR just marked ready waits one sweep. New knobs `CCC_SKILL_PROMOTION_APPROVE_CMD` (default: the managed Codex `gh-pr-flow/scripts/approve-via-relay.sh`, then the checkout copy; unresolvable → `approve_cmd_missing`), `CCC_SKILL_PROMOTION_APPROVE_PROFILE` (default `seoseo-ai`) and `CCC_SKILL_PROMOTION_APPROVE_SSH_TARGET` (no default → `approve-not-configured`), all accepted by the publisher config file; `status` and `effective` show `auto_approve: {mode, cmd_present, profile, ssh_target_set, blocker}` (presence only). With the mode not off, `promote` requests the profile's actor as reviewer at PR creation (the sweep re-requests it if missing); off leaves the `gh pr create` argv unchanged. First-time approvals and dry-run would-approves are reported to the owner from the promoter itself (push spool event `SkillPromoteAutoApprove`, counts and PR numbers only), so the 15-minute results cron reports too. `gh-pr-flow` (codex and claude copies) and `docs/skill-autosave.md` gain the matching "Standing approval for mechanical fleet-skills promote PRs" section: scope, conditions, everything else still per-PR fresh approval, and revocation by deleting the flag file. The off path's merge call also drops `--delete-branch`: fleet-skills `main` has a merge queue and gh refuses `-d` there, so every sweep merge attempt since the queue was enabled failed even after a human approval (seen on fleet-skills #430, 2026-10-11); the repo deletes merged branches itself.
