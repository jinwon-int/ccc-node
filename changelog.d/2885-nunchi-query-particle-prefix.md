- **nunchi recall matches inflected Korean words (#2885).** `facts_fts` uses FTS5's default tokenizer, which splits on spaces and punctuation only, so "배포를" in a question and "배포" (or "배포가") in a fact were different tokens and a whole-word query missed. `search()` — behind `recall`, `dialectic`, `why --query` and the SessionStart hint ranking — now also sends each Hangul word of the query as a prefix query on its stem (trailing particle removed with gotgan's rule; a stem shorter than two syllables is not used, so "결과" stays "결과"), and for a Hangul ending glued to a non-Hangul word ("PR에서") the head as a phrase. Everything the query sent before is still sent first, so the set of matching facts only grows; under a row limit bm25 still picks the rows, so a previously returned row can be displaced by a newly matching one. No index or stored data changes. Measured on one node's fact store (59 questions written from stored facts, read-only copy), on the `recall` path: keyword questions with the target among the 12 returned rows 0.88 -> 1.00 (MRR 0.47 -> 0.51), natural-language questions 0.93 -> 0.97 (MRR 0.52 -> 0.60); no target returned before dropped out. `NUNCHI_QUERY_PREFIX=0` restores the old query. `claude/hooks/nunchi/query-prefix.test.sh` pins the behaviour on a synthetic fixture.
