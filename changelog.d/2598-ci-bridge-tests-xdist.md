- **CI: `bridge-tests` runs the bridge suite in parallel with pytest-xdist (#2598).** The job was the harness-ci critical path (~540 s, ~5.5k tests run serially). `pytest-xdist` (and its `execnet` dependency) is added to the hash-locked CI toolchain (`.github/requirements/bridge-ci.in` → `bridge-ci.txt`, regenerated with `scripts/ccc-deps-lock.sh` on CPython 3.11; no other pin moved, the runtime lock is unchanged) and the coverage run uses `-n auto`; pytest-cov combines worker data, so the `fail_under` gate still covers the whole suite (locally 85.58 % both ways; 719 s → ~420 s on 3 cores). Parallel runs exposed a test-isolation leak: runtimes register in the process-global turn-liveness registry on construction, so an unclosed grok runtime leaked into `test_turn_stall`'s empty-registry assertion — hidden in serial runs only by file order. `bridge/tests/conftest.py` now snapshots and restores that registry around every test. A second contention-only race is fixed too: `test_danso_runtime.py::test_interrupt_or_cancel_reaps_child_and_preserves_journal` read the fixture child's pid file as soon as it existed, but the child writes it with `write_text` (truncate, then write), so a loaded run could read `''`; the test now waits until the file holds a number. The first CI run also hit `OSError: AF_UNIX path too long` in the hande socket suites (27 tests): xdist adds a `popen-gw<k>/` level under `tmp_path`, which with CI's `TMPDIR=$RUNNER_TEMP/ccc-tmp` overflowed the 108-byte `sun_path`. A new `short_tmp_path` conftest fixture (built on `tmp_path_factory`, falling back to a 0700 `mkdtemp` under `/tmp`) now backs `tmp_path` in `test_hande_transport.py` and `test_hande_steward.py`. And `test_hande_bot.py::test_transport_verdict_words_the_socket_not_a_sync_loop` set `_health_started = 0.0` to mean "past the 120 s startup grace", which only holds when `time.monotonic()` (≈ host uptime) exceeds 120 s — a fresh CI VM that reached the test sooner (as the faster parallel run did on 3.14) got `wait`; it now backdates from `time.monotonic()` like the matrix health-tick test.
