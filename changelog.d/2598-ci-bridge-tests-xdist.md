- **CI: `bridge-tests` runs the bridge suite in parallel with pytest-xdist (#2598).** The job was the harness-ci critical path (~540 s, ~5.5k tests run serially). `pytest-xdist` (and its `execnet` dependency) is added to the hash-locked CI toolchain (`.github/requirements/bridge-ci.in` → `bridge-ci.txt`, regenerated with `scripts/ccc-deps-lock.sh` on CPython 3.11; no other pin moved, the runtime lock is unchanged) and the coverage run uses `-n auto`; pytest-cov combines worker data, so the `fail_under` gate still covers the whole suite (locally 85.58 % both ways; 719 s → ~420 s on 3 cores). Parallel runs exposed a test-isolation leak: runtimes register in the process-global turn-liveness registry on construction, so an unclosed grok runtime leaked into `test_turn_stall`'s empty-registry assertion — hidden in serial runs only by file order. `bridge/tests/conftest.py` now snapshots and restores that registry around every test. A second contention-only race is fixed too: `test_danso_runtime.py::test_interrupt_or_cancel_reaps_child_and_preserves_journal` read the fixture child's pid file as soon as it existed, but the child writes it with `write_text` (truncate, then write), so a loaded run could read `''`; the test now waits until the file holds a number.
