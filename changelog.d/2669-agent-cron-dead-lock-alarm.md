- **agent-cron alarms when a due task keeps skipping on a dead holder's lock, and the periodic watches get a lockTimeoutSec (#2669).** A same-boot run lock is never stolen, and a `locked` skip is not a failure, so nothing fired when a package upgrade TERMed `ccc-agent-cron.service` mid-run on a fleet node (2026-11-05 06:21 KST): `fleet-watch-15m` skipped 16 due runs over 4.5 h in silence. `scheduler --execute` now counts, per distinct `scheduledAt`, enabled due tasks skipped for a lock with `holderAlive=false`; after 3 (`CCC_AGENT_CRON_DEAD_LOCK_ALERT_AFTER`, 0 disables) it spools one owner alarm (`dead-lock=threshold`, tier `action`, with the holder run id and release command) and one `dead-lock=recovered` info notice once unblocked. It ignores the task's `notify` and `failureAlertAfter` (the watches set that to 0). Counters live in `failure-alarm.json` `deadLocks`; nothing is released automatically; dry-run modes only expose `holderAlive`. Docs: rule `lockTimeoutSec = 2 × timeout-sec, ≥ 600`, install examples updated (`fleet-watch-15m` 1800, `a2a-broker-worker-watch` 600) and `agent-cron.sh edit … --lock-timeout-sec` for nodes that already run them.
