- **The timed-test follow-up scan now has its own cron installer (#2324).** `scripts/install-timed-followup-scan-cron.sh` (dry-run by default, `--apply`, `--remove`) renders one managed entry, marker `# ccc-node:timed-followup-scan`, that runs `timed_test_deadline_scan.py --mode followup --include-closed-days N --notify LEVEL --exit-nonzero-on-findings` once a day at 09:35 KST against the deadline scan's repos file. It logs to `timed-followup-scan.cron.log`. Defaults are `--include-closed-days 45` and `--notify high`, with env overrides under `CCC_TIMED_FOLLOWUP_SCAN_*`, and every option is written to the install record so a self-update replay keeps it. It is separate from `install-timed-test-deadline-scan-cron.sh` for three reasons: followup mode reports only followup findings and would replace the `expired` entry, install records are one per installer file, and neither marker is a prefix of the other, so installing or removing one lane leaves the other's block alone. ccc-doctor registers the marker (`cron gen timed-followup-scan`), and followup-mode owner notices now point to the new log.
- **A cut agent-cron owner notice now keeps a local full copy and says where it is (#2324 (3), option B).** When a notice has to cut a shown stream at 900 characters, the full notice, with the same redaction, is first written to `~/.claude/state/agent-cron/full-output/<runId>.txt`. The file is 0600 and written atomically into a 0700 directory that is never opened through a symlink; `CCC_AGENT_CRON_FULL_OUTPUT_DIR` overrides the location. The notice ends with that path, and the spool record and run result carry `fullOutputPath`. The newest 200 files are kept. Previously the rest of the body was dropped without any marker. Owner recipients only. Nothing is written to GitHub or any other remote.
