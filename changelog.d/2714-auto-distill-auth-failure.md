- auto-distill no longer parks finished sessions when the extractor CLI cannot authenticate (#2714). On 2026-10-28 one node's Piri engine exited rc=3 with an xAI OAuth `invalid_grant` for twelve days; the failure was counted as a model-quality failure (`model_exit_3`), so every session was dead-lettered after three ticks, the cause was cut away, and nobody was told. Auth patterns (`invalid_grant`, OAuth refresh failures, HTTP 401/403, invalid API key / `/login`, unauthorized, expired tokens) now classify as a transport failure (`model_unavailable`) — spending the 48-tick transport budget and opening the per-run circuit breaker instead of the quality budget — and Claude `is_error` envelopes with auth text do the same. A transport reason carries one fixed, body-free cause token (`auth_invalid_grant`, `auth_oauth_refresh`, `auth_401`, `auth_403`, `auth_invalid_key`, `auth_unauthorized`, `limit`, `network`, or the existing `error_envelope`/`no_model_usage`/`exit_N`/exception name), recorded as `cause` in the watermark failure state, the `extract_fail`/`dead_letter` audit rows and the run summary; CLI text is still never kept. A run that tried and extracted nothing extends a streak in `~/.hermes/state/auto-distill-health.json`; after `CCC_AUTO_DISTILL_ALERT_RUNS` consecutive such runs (default 6 ≈ 3 h, `0` disables; idle runs neither extend nor reset it; an engine-selection failure counts) one `AutoDistill` owner notice (`tier=notice`) is queued on the bridge push spool, and one recovery notice follows the first successful extraction. Parked sessions are reprocessed with the existing one-shot `--revive-dead-letters` (#1831). The non-zero-exit limit/network suffix changes from `exit_N` to `limit`/`network`; the persisted `reason` stays `model_unavailable`.
