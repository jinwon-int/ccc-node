- **fleet-watch: a Matrix probe that times out is UNVERIFIED, not UNREACHABLE (#2766).** `fleet-matrix-watch.sh` reported every empty answer as `UNREACHABLE <node> channel=matrix`, whatever ended the attempt. On 2026-11-11 the T2 watcher needed 5.6–14.0 s for `ssh true` to one healthy Termux node (key exchange done by 3.4 s, authentication by 11.1 s), two runs in a row hit the 10 s limit, and the owner was paged about a Matrix frontend that had been retired on that node for four days. The empty answer is now classified by the last attempt's exit code, as the hande watch has done since #2673: `UNREACHABLE` only for an ssh transport failure (255); `UNVERIFIED … inspection=probe-timeout` for a timeout (124), i.e. a node that accepted the connection but did not finish inside the limit; `UNVERIFIED … inspection=probe-error rc=<n>` for a probe that died, and for the local node. `fleet_watch_state.py` confirms `UNVERIFIED` over three runs instead of two, so two slow runs followed by an answer no longer page; three slow runs in a row still do, under the accurate name. The 10 s limit and the single retry are unchanged — raising the limit to the hande watch's 20 s would put the light-mode worst case (504 s + 504 s) past the 840 s task timeout, which #2766 keeps open together with sharing one ssh session between the two watches. `fleet-matrix-watch.test.sh` 9→20 PASS; the new assertions fail on the previous script.
