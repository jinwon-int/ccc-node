- **The Termux MemPalace installer pins MemPalace 3.12.0 and upgrades in place from either previous managed pin, 3.10.0 or 3.11.0 (#2662).** The default and only accepted `CCC_TERMUX_MEMPALACE_VERSION` is now `3.12.0`, the managed freeze carries `mempalace==3.12.0`, and `upgradable_from` lists `3.10.0 3.11.0`, so a node one or two pins behind lands on the current pin in one run under the existing rule: the installed lock must differ from the managed freeze only in its `mempalace==` line, otherwise the run fails closed. 3.12.0 declares the same dependencies as 3.11.0 and only raises `requires-python` to `>=3.10`; the Debian 12 guest runs Python 3.11. The memory probe accepts `3.12.0` as a managed Termux pin, so an upgraded node does not read `error` (#2514 contract). After the upgrade, the first sweep re-reads every source once while reusing stored vectors, and `hallways.json` moves into `hallways.sqlite3` (upstream 3.12.0 notes).
