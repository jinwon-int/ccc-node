- `detached_jobs.py` completion notices now carry a fleet-alert tier, and scheduled jobs work on non-root nodes (#2710). The spool record had no `tier`, so every notice was `info`: held for the next 09:00 KST digest and never mirrored to 「한데」 on its own — a job ending at 09:30 was read the next morning. `notify` and `schedule` take `--tier info|notice|action|critical` and `--fail-tier` (used for a non-zero exit); `schedule` defaults to `notice`, bare `notify` keeps `info` and its usage now says so. `schedule --user` launches `systemd-run --user`, records `scope=user`, and warns when `loginctl` reports `Linger=no`; the sweep asks `systemctl --user` for `scope=user` rows (also `register --user` for hand-made user units), so an armed user timer is `running`, not a false `lost`. A non-root system `systemd-run` authentication failure now suggests `--user`. `--result-file <path>` appends the job's last non-empty result line (whitespace-collapsed, ≤280 chars) to the notice. `bridge-safe-detached-run` Step 2d documents both traps.
