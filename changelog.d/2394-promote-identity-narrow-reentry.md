- **A promote PR the generator flagged for fleet identities can now re-enter the #2239 L3 standing-approval path, but only after a flagged-line-only fix (#2394, owner decision 2026-10-20: narrow re-entry).** Before, `_sweep_promote_merge` held every batch whose creation-time ledger row had `identity_hits` (`needs-human-identity`), even after a human fixed exactly the lines the PR body listed and marked the PR ready. That made one flagged line cost a full human review and merge, while the body ("edit them, then mark ready") suggested the sweep would carry on. Now, when L3 is on and a human has marked the batch ready, the sweep compares the recorded generator commit with the live head (`compare/<creation>...<head>`, linear history only). The batch re-enters only when the change touches just the creation-time hit lines of the flagged `SKILL.md`: same file, same line numbers, no line added or removed, no other file. A rescan of that exact head must also find no identity hit there. Every existing L3 condition then still applies unchanged: full-diff path allowlist and rescan, `--expected-head`, `--match-head-commit`. A re-entered batch is merged only on an L3 approval of that head, never through the plain pre-L3 merge, and every other edit stays human review + merge.
- Each decision is recorded once per (creation head, head) as a new ledger row `a2a-promote-rescan` (`pr`, `creation_head`, `head`, `outcome` `eligible`|`not-eligible`, reason codes, never matched values). An unchanged head reuses the recorded decision with no API call; a read failure is not recorded and retries next sweep. `_promote` now records the generator commit as `creation_head` on the `a2a-promote-pr` row. Older rows without one fail closed (`creation_head_unrecorded`) instead of guessing the commit from forgeable git author metadata.
- With L3 off the hold is unchanged (no API call). The sweep never marks an identity batch ready itself, so #2360's publisher-ready rows keep their meaning. Dry runs report `would-hold-identity-hits` (with `rescan: would-rescan-when-ready` when L3 is on) and touch nothing.
- The promote PR body now says what keeps the L3 path: edit only the flagged lines and mark ready; any other edit, including an audience move, needs a human review and merge. The gh-pr-flow L3 policy section (claude and codex copies) states the narrow rule.
