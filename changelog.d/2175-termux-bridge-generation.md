- **`scripts/termux-bridge-generation.sh` manages prepared bridge generations on Termux (#2175 C).** Switching a Termux node to a new commit meant hand-running a worktree add, the provider `.env` link, `termux_prepare.py` with the right interpreter, the gate, a pointer swap, a recovery-armed restart and a Matrix restart; each was missed at least once (missing `.env` → exit 6, inherited venv `PATH` → backend probe failure). `prepare <rev>` now builds a generation (same-node wheel reuse with automatic full-build fallback, optional `--extra matrix`, serving gate) and `promote <gen>` gates, waits for an idle turn, swaps `~/.ccc-node/bridge-current` atomically, restarts Telegram with one-shot recovery to the previous generation, rolls the pointer back on failure, and detaches an idle-gated Matrix follow. `launch`/`print-source`/`print-job`/`status` replace the operator-side `bridge-current.sh`, whose `--path … --restart -d` contract still works.
