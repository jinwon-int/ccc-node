- **`scripts/fleet-ssh-mesh.sh verify` warns when a fleet alias is also defined outside the managed block (#2687, proposal 5).** After the N×N check, `verify` reads each reachable node's `~/.ssh/config` (read-only) and prints `VERIFY-WARN <node> ~/.ssh/config:<line>: Host '<alias>' is also defined outside the managed block, ...` for every `Host` pattern outside the `SEOYOON-FLEET-MESH` block that names an alias the block defines. The line says which definition `ssh` uses: an entry before the managed one wins for every option it sets; an entry after it is shadowed for the options the block sets, while its `IdentityFile` lines and options only it sets (e.g. `ProxyJump`) still apply. Warnings do not change the exit status, which stays the N×N result, and no file is modified. Understood: keyword case, leading blanks, `Host=name`, several patterns per line, quoted patterns, trailing comments; names compare case-sensitively as in `ssh`. Not reported: wildcard and negated patterns (`Host *`), `Match` blocks, `Include`d files. A config with unbalanced markers or one that cannot be read gets one `alias check skipped` warning. This is the detection half of proposal 5; removing the old alias entries on the nodes is not part of this change. Docs: `docs/fleet-ssh-mesh.md`.
