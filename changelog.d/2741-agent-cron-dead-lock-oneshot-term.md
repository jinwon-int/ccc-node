- **agent-cron: the dead-lock alarm reaches one-shot tasks, and SIGTERM no longer leaves a run lock behind (#2741, follow-up to #2669).** Two gaps in the dead-lock protection. (1) The alarm counted distinct `scheduledAt` values and fired at 3: a one-shot `at` task has one due run, so its counter stopped at 1 and it never alerted (a daily task took two more days). The alarm now also fires once the lock has been dead for `CCC_AGENT_CRON_DEAD_LOCK_ALERT_AFTER_SEC` (default 1800, `0` disables only this trigger) since the first skipped tick; the event carries `trigger` (`skipped-runs`/`blocked-time`) and `blockedSeconds`, and the text says how long the task has been blocked. `CCC_AGENT_CRON_DEAD_LOCK_ALERT_AFTER=0` still turns the whole alarm off. (2) `agent_cron.py` had no SIGTERM handler, so the unit's `TimeoutStartSec` (1800 s, shorter than a prompt task's 3600 s default) or a package upgrade restarting services killed the scheduler between `acquire_for_run` and the `finally` that releases the lock — a dead lock, no history entry, no notice. A run now handles SIGTERM for its own span: the running task is abandoned and recorded as a failed run with exit 143 (history, owner notice, retry backoff and `maxRuns` apply), the lock is released, tasks not yet started stay due, and the scheduler exits 143 with `terminatedBySignal` in its JSON. A signal outside the task's own work is deferred until the current store/lock/spool write finishes; other subcommands keep the default action. `agent-cron.test.sh` 174→185 PASS (5 of the 11 new assertions fail on the previous code), `agent_cron_alarm_test.py` 60→67.
