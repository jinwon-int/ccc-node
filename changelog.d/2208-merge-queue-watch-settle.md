- **gh-pr-flow `merge-queue-watch.sh` no longer reports a merged PR as evicted** (#2208). The queue removes the entry when it squash-lands, so a merge landing between the watcher's PR read (`OPEN`) and its queue read (empty) was reported as `evicted` (exit 10) — observed on pr-shepherd#154, which had merged. An empty entry is now re-confirmed `--settle-tries` times (default 3, `--settle-delay` 5 s, capped at `--interval`) by re-reading the PR and the queue: `MERGED` → `merged`, `CLOSED` → `closed`, a reappearing entry keeps watching, and only a still-`OPEN` PR with no entry yields `evicted` (or `not-enqueued` on the first poll). `--settle-tries 0` restores the immediate verdict. Five hermetic cases added to `merge-queue-watch.test.sh`.
