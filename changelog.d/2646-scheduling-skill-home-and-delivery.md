- skills: `scheduled-verification-with-session-fallback` adds two rules for the scheduled check itself. System units run with `HOME` unset, so a literal `$HOME` path breaks only the local node's row (it reads as `none`/`0`, not an error): set `Environment=HOME=` or `export HOME`, with a one-line probe. A chat/spool notification is not delivery: the script posts the verdict to its tracking issue, or the next session gets a pending-publish line in `working-state.md`. One-shot units disable themselves after running, and a disabled unit's tracking issue is read before re-enabling it. Field case: a fleet re-check ran on time and passed but was never posted, and its local row read `t0=none` (#2646).
