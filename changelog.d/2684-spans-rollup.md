- **Daily span rollup (#2684 slice 3).** New `scripts/spans-rollup.py` summarises one KST day (default yesterday, `--date`) of the bridge span ledger (`.telegram_bot/spans/`, both overlapping UTC files): per tool calls, error rate and p50/p95 `duration_ms`; per model turns/tokens/cost; turn status/outcome/`error.type`, `ccc.skill` counts when present, and `kind=a2a` top-5 failure classes only when such spans exist. Turn totals are cross-checked against `.telegram_bot/usage-cost-ledger.jsonl` (turns, input excl. cache, output, cost) with a discrepancy % per metric and the < 5 % target. Every span passes the canonical `span_ledger.sanitize_span` allow-list first (loaded by path; exit 4 and no delivery if unavailable), so only aggregates and allow-listed identifiers are emitted. Delivery: one `metrics/span-rollup` entry in the human-gated `wiki-candidates.md` queue (idempotent per date+node) and one owner-only `tier=info` push-spool record (`event=SpansRollup`) for the fleet-alerts 09:00 KST digest, whose file name is recorded in the entry; `--no-digest`, `--dry-run`, `--json`. Missing dir, empty day and corrupt lines exit 0 (empty day delivers nothing). Scheduled by the new opt-in `install-cost-ledger-cron.sh --spans` line (03:41 KST, materialized in the install record). New suite `scripts/spans_rollup_test.py` (ci.yml python-lint).
