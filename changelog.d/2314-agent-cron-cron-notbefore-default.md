- **agent-cron no longer fires last year's occurrence for a freshly added date-pinned cron task (#2314).** A never-run cron-kind task without `notBefore` scans occurrences from 366 days back, so a one-shot such as `0 9 15 10 *` with `maxRuns 1` added on October 14 was due immediately with `scheduledAt` of the previous October 15, burned its only run, and was disabled before the real date. `add` now defaults `notBefore` to the creation time (UTC, seconds precision; `add --at ISO8601 <task-id>` overrides the clock, an invalid `--at` exits 2 without writing) for cron-kind schedules when `--not-before` is not given, so the existing `notBefore` floor starts the scan at creation. No new task field: `notBefore` is already in the schema, so a rollback to an older build can still read the store. An explicit `--not-before` is kept, interval and `at` one-shot schedules are not stamped, the `lastRunAt` floor is unchanged, and existing tasks in the store are not rewritten. To allow a deliberate catch-up, pass an earlier `--not-before`.
