- **Skill autosave drafts are gated at draft time — trigger wording, near-duplicates and a per-session cap run before a draft enters `pending-skills/` (#2239, lane L2; follows #1647).** Until now `skill-review.sh` staged any candidate with a name and a frontmatter fence, and the two checks that produce 85%+ of the fleet intake "revise" verdicts (missing trigger wording, duplication) only ran downstream. The staging loop (manual and the SessionEnd hook alike) now rejects a candidate whose `description` lacks trigger wording (`description_trigger.py`, the fleet-skills `TRIGGER_RE` copy), whose name/description resembles an installed skill of the drafting provider (Jaccard ≥ `CCC_SKILL_DEDUP_JACCARD_PCT`, default 60) or an undecided draft already in the queue (stricter `CCC_SKILL_DEDUP_PENDING_JACCARD_PCT`, default 75), and any candidate beyond `CCC_SKILL_REVIEW_MAX_CANDIDATES` per session (default 1; `0` = no cap). Rejected drafts are never deleted: they land in `skill-autosave-archive/draft-rejected/<id>/` (0700/0600) with the normalized `SKILL.md`, `meta.json`, a `reject.json` (`reason` = `description-trigger` | `duplicate` + `matched` | `session-cap`, session, ts, name) and a `manifest.jsonl` row, the review log gets `candidate rejected reason=<reason> name=<name>`, `skill-review-last.json` gains `staged`, `draft_gates` and `rejected: {trigger, duplicate, session_cap}`, and `ccc-skill-autosave.sh pending-restore <id>` can put one back into the queue. `CCC_SKILL_REVIEW_DRAFT_GATES=off` bypasses all three gates (default on); a missing `python3`/helper logs a pass-through instead of rejecting blind, since autoinstall and promotion still fail closed behind this pre-filter. The dedup pieces (`norm_name`, `desc_tokens`, `gate_dedup`, thresholds) moved out of `autoinstall.sh` into the shared `claude/hooks/skill-review/gates-lib.sh`; the installer sources it and its behavior is unchanged.
