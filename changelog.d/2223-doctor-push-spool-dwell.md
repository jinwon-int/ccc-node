- **`ccc-doctor` now reports push notifications that nobody delivers (#2223).** On one node Telegram push was turned off while the Matrix consumer drained an overridden `matrix-spool`. Every cron/hook writer kept its default `telegram-spool`, so 9 owner notices sat undelivered for a day. Writers reported `delivery: spooled`, and the bridge health probe only counts the directory its own process consumes. Another node had the same orphan in a root-lane spool next to a user-lane bridge. The new read-only `push spool dwell` row flags any `*.json` record still pending after 30 minutes (`CCC_DOCTOR_PUSH_SPOOL_DWELL_MINUTES`, `0` disables). It checks the writers' default dir (marked `writer-default`), every `*-spool` dir in this and other readable accounts' state dirs (`CCC_DOCTOR_PUSH_STATE_ROOTS` overrides), and fan-out mirror subdirs, deduplicated by resolved path. It reads only file names and mtimes: no record bodies and no other process's environment. `docs/matrix-frontend.md` now warns that the remaining consumer must drain the writers' directory when one frontend's push is turned off.
