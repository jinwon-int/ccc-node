- **`ccc-doctor` now warns when an account that does not run the harness still wires Claude hooks (#2323).** `setup.sh` and self-update only refresh the account whose home the live bridge serves, so a retired lane's `~/.claude/settings*.json` keeps firing frozen hooks in any session that account opens (observed: a retired root lane ran 17 hooks from 09-11 once a root login was issued). The new read-only `nonharness-account-hooks` row scans `/root`, `/home/*` and the doctor's own account, skips the harness (every bridge-served `--path`, every bridge owner's login home, and any `~/.claude` resolving to a harness one), and reports path, hook count and sanitized event names only — never command text. Accounts it cannot read, symlinked settings and unparseable files are listed, not flagged; another account's file can never abort the doctor run. Nothing is edited. Test seam: `CCC_DOCTOR_ACCOUNT_HOMES`.
