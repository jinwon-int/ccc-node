- **`bridge-watchdog.sh` no longer mistakes a Matrix frontend for the Telegram bridge (#2176).** The Matrix frontend runs the same `python -m telegram_bot --path $HOME` command line, so the pgrep fallback counted it as "Telegram is up" and a dead Telegram bridge was never restarted while Matrix stayed healthy (daegyo crond, 2026-10-08). Both the `bot.pid` alive check and the fallback now apply `bridge/start.sh`'s channel rule: a process whose `/proc/<pid>/environ` carries `CCC_CHANNEL=matrix` is a different service; an unreadable environ or any other value still counts as Telegram, so a live bridge is never turned into a false "down". Debounce and the start lock are unchanged. `bridge-watchdog.test.sh` adds four cases (Matrix-only alive → restart, Telegram alive next to Matrix → no restart, `bot.pid` recycled onto the Matrix pid → restart, unreadable environ → no restart); the two Matrix cases fail against the previous script.
