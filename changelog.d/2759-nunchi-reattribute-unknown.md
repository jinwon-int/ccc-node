- **`nunchi.py reattribute-unknown` moves legacy `observed=unknown` facts to the node name, dry run by default (#2759, #2542 제안 3).** Until 2026-10-28 a node whose cron ingest had no `CCC_NODE` and no `state/node.txt` stored every `subject=node` fact under `observed='unknown'` (#2541). #2542 fixed the inflow and left the stored rows as a separate DB change; on 2026-11-11 six nodes still held 3,748 open rows of that kind, none newer than 2026-10-28. This adds the command for that step. Merging it changes no database: applying it is a per-node owner decision. The target is the node's own identity, or `--node NAME` when that does not resolve; the command exits non-zero before opening the database when the name is `unknown`, off the roster, or contradicts the resolved identity. Only rows it can prove are `subject=node` facts are in scope: the stored `dedup` must equal `sha1("<observer>|node|<fact>")`, or the `supersede` key while the `supersedes` parent is itself in scope. Any other `unknown` row is reported as `unproven` and left alone. The dry run prints counts (total, open, closed, by kind, by proof), how many rows would be renamed, closed as duplicates or skipped, and a body-free sample (`--sample N`; `--show-text` adds truncated text; `--json`). `--apply` works in one `BEGIN IMMEDIATE` transaction. It sets `observed` on open and closed rows and changes nothing else: text, kind, `source_rank`, `review`, timestamps and `dedup` stay (the dedup key never contained the observed peer, so a re-fed payload remains a no-op), and no ingest gate is re-run. An open legacy row whose kind and text already exist as an open fact under the node name is renamed and closed with a `merged-away:#<id>` token instead of becoming a second open copy; the existing fact is never touched, and a legacy row that outranks it stays open (G2). `facts_fts` indexes `observed` and has no update trigger, so the same transaction runs an FTS5 `rebuild`: node-name recall finds the rows afterwards and `unknown` no longer does. Every change is recorded in the body-free `reattribute_unknown` ledger; a second `--apply` changes nothing, and `reattribute-unknown --revert [--apply]` restores the ledgered rows (previous peer, reopened duplicates, index). `nunchi.py metrics` now prints `observed_unknown_open`. `docs/nunchi-curation-authority.md` lists the command under Tier 2, `curation-authority.test.sh` pins what it may write, and `reattribute-unknown.test.sh` covers it against a temp database.
