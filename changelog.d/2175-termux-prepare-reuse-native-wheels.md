- **`termux_prepare.py --reuse-wheels-from <prior-job>` reuses a same-node job's native wheels when nothing that determines them changed (#2175).** Every Termux generation rebuilt the five native wheels from scratch (about 45 of 50 minutes) even with an unchanged lock, and one Termux node produced bit-identical wheels three builds in a row. The new flag accepts only a ready, owner-private prior job whose receipt matches this run's Android API, linker profile, both lock hashes and full toolchain record; it seeds the private pip wheel cache, verifies every native wheel digest, and fails with `reused_wheels_not_used` if bootstrap built one again. Fresh install, readiness and `--verify-reinstall` still run, and the receipt records `native_wheels` mode and source. Measured: 262s instead of 3015s. The driver also now refuses to run from a venv interpreter (`must_run_with_base_interpreter`) instead of failing the backend probe with `No module named 'maturin'`.
