- **The promote merge sweep no longer records a merge it did not get (#2264).** `gh pr merge` exits 0 after *enabling auto-merge* on a repository that allows it (fleet-skills does) and after *enqueueing* on a merge queue; the sweep wrote `state: MERGED` to the ledger on exit 0 alone, `_open_promote_prs` then skipped the still-open batch, and `_promote` opened a duplicate PR every tick — 22 open copies of the same two-skill batch (fleet-skills #435–#456, 2026-10-11/12) and one `SkillPromoteAutoApprove` dry-run notice per copy. Two changes: (1) without an approval of its own (`off`/`dry-run`) the sweep does not call `gh pr merge` on a PR whose `mergeStateStatus` is `BLOCKED` (branch protection waiting for a review) → `waiting-review`; `true` mode still approves first and then enqueues as before. (2) After any merge call it re-reads `state,autoMergeRequest` live and records `MERGED` only when GitHub reports it; OPEN → `promote-pr-auto-merge-enabled` or `promote-pr-merge-pending` with the ledger row left OPEN for the next sweep's live read, unreadable → `promote-pr-merge-unverified`. Tests cover the auto-merge-enabled, queued, unreadable and BLOCKED shapes in both the pre-L3 and L3 sweeps; `docs/skill-autosave.md` describes the new outcomes.
