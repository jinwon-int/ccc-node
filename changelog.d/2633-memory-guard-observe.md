- **`scripts/memory_guard_observe.py`: per-restart memory-guard observer (#2633 a).** A one-shot `memory.peak`/`memory.events` read keeps only what the cgroup has counted since it was created: self-update restarts drop earlier cycles, and a stop that leaves unit processes behind reuses the cgroup so the counters span restarts (sogyo/hande showed the same `1.9G memory peak` on four consecutive stops, 2026-11-01). The read-only observer reports, per `ccc-*bridge*.service` (or `--unit`): per-stop peak/swap peak from the journal `Consumed … memory peak` lines with the count of processes that survived each stop, whether the current start reused the cgroup, `memory.events` growth since the previous run (`--state-file`, keyed by `ControlGroupId`; a recreated cgroup resets the baseline), and PSI `memory.pressure` some/full avg300. Verdict from the delta and oom-kill, not from a PID change: FAIL on max/oom_kill growth or a journal oom-kill, WARN on high growth, an inactive unit, peak or cycle peak ≥ `--warn-pct` (80) of `memory.high`, or PSI some avg300 ≥ 10. Exit 0/1/2/3 = PASS/WARN/FAIL/UNVERIFIED. Numbers and counts only — journal text is never echoed.
