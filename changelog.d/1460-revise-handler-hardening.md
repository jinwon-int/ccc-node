- **The skills-intake revise handler now bounds a hung reviser with `timeout -k` (#1460 P2).** The reviser ran under a plain `timeout`, so an agent that ignored SIGTERM could outlive the budget. It now runs as `timeout -k "$REVISE_KILL_GRACE_SEC" "$REVISE_TIMEOUT_SEC"` (grace defaults to 30s, the same `-k 30` the headless runners use). A malformed or zero timeout or grace is refused as node config (exit 1). The log tells a timeout (124) apart from a SIGKILL after the grace (137). The run is now a background job plus `wait`, so a TERM/INT/HUP that the worker sends to the handler is forwarded to the reviser instead of leaving it orphaned. The EXIT trap still removes the temp dir.
- **The revise handler enforces the reviser tool lock instead of only defaulting to it (#1460 P2).** An override of `REVIEW_AGENT_ARGS` is accepted only if it keeps a total lock: `--disallowed-tools *` / `--disallowedTools *` (or the `=*` form), `--no-tools`, or the `danso-review-agent.sh` wrapper, which always runs danso with `--no-tools`. Otherwise it fails closed with exit 1 before the agent starts. That covers a dropped lock, a lock narrowed to anything other than `*` (including a literal quoted `"*"`), and an added allow-list or permission bypass (`--allowed-tools`, `--allowedTools`, `--tools`, `--dangerously-skip-permissions`). Exit 1 because this is node configuration, not a packet result.
- **The revise handler resolves the reviser node id once (#1460 P2).** The prompt bindings, `output.reviser_node` and `validations[].nodeId` now share one value, in this order: `WORKER_ID`, `A2A_WORKER_ID`, `hostname -s`, `unknown`. Before, the prompt could name the host while the result said `unknown`. The revise round is also resolved once (default 1), so the prompt no longer says `?` while the result says 1.
- **The revise handler's size caps are symmetric and explicit (#1460 P2).** The packet's `skillFiles` are now checked against the same 16 files / 64 KiB per file / 256 KiB total that bound the returned files and the publisher. An over-cap packet fails (exit 1) before any reviser run. Before, the reviser ran on it and the result then hit the return cap. Raw reviser stdout is capped at 1 MiB (an oversized result, exit 3). Returned content that cannot be encoded as UTF-8 is now an unsafe result (exit 3) instead of a composer crash.
