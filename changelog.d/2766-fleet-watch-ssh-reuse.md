- **fleet-watch: one ssh connection per node per run instead of three (#2766).** A sweep opened a new ssh connection for each channel of every node — Matrix (10 s limit), 「한데」 (20 s), bridge (30 s) — and from a far watcher the handshake is nearly the whole probe and the part that stalls. Measured 2026-11-13 from the T2 watcher (medians of 6): a Matrix probe to the three slow-link nodes took 4.2–4.6 s over a new connection and 1.2–1.6 s over an open one (0.4–2.6 s against 0.1–0.7 s for the eight other nodes), and the ssh time of one run (11 remote nodes × 3 channels) drops from 82 s to 42 s. In the 740 scheduled 15-minute runs of 2026-11-06..13 those three nodes produced all 81 unanswered probe rows (Matrix 32, 「한데」 27, bridge 22), five of which paged the owner. `fleet-bridge-watch.sh` now lets the first probe of a node open the connection (OpenSSH `ControlMaster=auto`, `ControlPersist=120`, sockets in a 0700 directory under `${TMPDIR:-/tmp}` that the run closes and removes on exit) and the other two ride it; the 「한데」 watch runs before the Matrix watch, so the one handshake gets the 20 s limit and the Matrix probe no longer spends its 10 s on connecting. A retry always connects on its own (`ControlPath=none`), so a stale shared connection costs one attempt and never the verdict; a node name that is not a plain file name, a socket path too long for a unix socket, an unusable `TMPDIR` or a missing `scripts/lib/fleet-ssh-reuse.sh` mean no reuse, never an error. Verdicts, limits, retry counts and the worst-case probe time are unchanged (the 「한데」 rows now precede the Matrix rows in a plain report; closing the connections adds about 0.01 s per node, at most 3 s); `CCC_FLEET_SSH_REUSE=0` restores one connection per probe, and the channel watches run on their own connect as before. A real 12-node `--light` run from the T2 watcher took 88 s without reuse and 47 s with it, with identical verdicts. New `fleet-ssh-reuse.test.sh` (hermetic, recording ssh stub).
