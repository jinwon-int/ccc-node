- **self-update / setup: a crash-looping service is no longer recorded as an activated update, and a rollback takes the skill manifests with it (#2742).** Two paths where a failure was recorded as success or left the node inconsistent. (1) After `systemctl restart`, self-update accepted the first `is-active`. A `Type=simple`, `Restart=always` unit is active the instant it forks, so a bridge that died two seconds into start-up (import or config error) cleared the pending-activation record, was audited `ok` and announced "self-update 완료" while systemd looped `activating (auto-restart)`. Each restarted allowlisted unit is now watched for `CCC_SELF_UPDATE_RESTART_STABLE_SECONDS` (default 15, 0..120, `0` = old behaviour): it must stay active and systemd must not have started it again (`NRestarts` and `ActiveEnterTimestampMonotonic` unchanged; properties systemd does not report are skipped). A unit that fails the window is a restart failure — exit 7, pending record and recovery snapshot kept, audit entry with `"unstable":true`, notice naming how it fell over — and is not restarted a second time. A changed tick takes that many seconds longer per allowlisted service. (2) The install manifests (`state/repo-{skills,commands,output-styles}.manifest`) live under `state/`, which is not a managed path, so both rollbacks (`setup.sh`'s own and self-update's) restored the trees but left the manifests of the release they had just undone. The next run saw current(v1) ≠ recorded(v2) with repo(v2) = recorded(v2), read it as "node-modified, repo unchanged" and kept the old skill on every later run; a skill the undone release had removed came back and was never pruned. Both rollbacks now snapshot and restore exactly those three files (`CCC_MANAGED_STATE_FILES`; nothing else under `state/`), remove one the failed run created, and refuse a symlinked manifest before setup runs. `setup.test.sh` runs the three-run scenario for real (install, fail after the skills step, run again): 3 of its 7 assertions fail on the previous code. `ccc-self-update.test.sh` 439→462 PASS, `setup.test.sh` 259→266, `harness-paths.test.sh` 16→26. Not in this change: the third group in #2742 (30-minute lock expiry vs a long prepare, the "보류" notice suppressing a later failure notice, the deferral cap vs tick interval) and the Piri manifests, whose trees are not rolled back either.
