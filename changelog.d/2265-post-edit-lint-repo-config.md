- **`post-edit-lint.sh` now defers to the repo's own ruff config and reports only findings on edited lines (#2265, follow-up to #2261).** The hook always passed `ruff check --select E,F`, and a CLI `--select E` re-enables a configured `ignore = ["E501"]`, so a one-line edit in this repo returned 98 pre-existing E501s that CI (plain `ruff check`) does not flag. When `ruff.toml`, `.ruff.toml` or a `pyproject.toml` with a `[tool.ruff` table sits between the file and the git root (or `/` outside a repo), no `--select` is passed and ruff's own config discovery decides; without a config `--select E,F` stays.
- For a file tracked at HEAD, rule findings are kept only on lines touched by `git diff -U0 HEAD` (a pure deletion touches the adjacent lines); the rest are counted in a trailing `(N pre-existing finding(s) outside the edited lines not shown)` line and the hook stays silent when only pre-existing findings remain. Syntax errors are always kept. Untracked/new files, repos without HEAD, non-git paths and diff failures fall back to the whole file. The header, `additionalContext` shape and always-exit-0 contract are unchanged; the body-free log gains `rules=repo|default preexisting=N`.
- Known limitation: a finding a change causes on an untouched line (deleting the last use of an import gives F401 at the import line) is hidden until CI.
