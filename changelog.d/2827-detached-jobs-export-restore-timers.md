- **Detached jobs (#2827): `export-timers` / `restore-timers` bring `schedule`d timers back after a reboot.** A `schedule`d job is a transient timer under `/run`, so a reboot erased it and the job never ran; on 2026-11-17 seven timers on three nodes were re-created by hand from saved `systemctl cat` output, and a first attempt that copied only `OnCalendar` and `ExecStart` left the services without `Environment=`. `schedule` now saves the exact `systemd-run` argv it launched in the registry row (`launch_argv`: run time, command, `Environment=HOME/PATH`, working directory, `--user`). `restore-timers` replays that argv for every scheduled job that has not started and whose timer is gone, so the job keeps the environment it was scheduled with and not the restoring shell's; a timer that is still armed is `kept` and never launched twice, and `--dry-run`/`--print` launches nothing. `export-timers [--out FILE]` writes the pre-reboot snapshot (owner-only): the same jobs plus each live unit's `systemctl cat` values, and `restore-timers --from FILE` compares the re-created unit with them by value — two `Environment=` assignments on one line equal one per line — reporting `differs` on a mismatch. Not restored, reported with exit 1 instead: a job whose one-shot time passed while its timer was gone (`missed`; it is not re-armed for a later time), a row written before this change or whose saved argv does not match its unit, scope or time (`unrestorable`; the snapshot keeps its live values for a re-creation by hand), and a `systemd-run` that refuses (`failed`). An unexpected error in these two commands exits 1 with a message; the sweep still fails open. The `bridge-safe-detached-run` skill and the `schedule` usage text name the two commands as the reboot procedure. Unchanged: the timer `schedule` creates, the sweep's done/running/lost classification, `register`/`notify`/`ack`/`list`; `restore-timers` does not write the registry. Out of scope here: a `--durable` persistent unit (proposal A), and timers made by a bare `systemd-run` outside `schedule`. `restore-timers --from` reads a snapshot only when the file is owned by the calling user and not group- or world-writable, because a snapshot row can stand in for a job the registry no longer has and its argv is then run.
