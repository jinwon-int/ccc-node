- **tunnel-audit: a failed listener scan is now `DEGRADED`, never a clean or accepted baseline.** One fleet node's `/usr/bin/ss` was a 0-byte file from 2026-09-02 to 2026-11-22. The collector reported `tools.ss_status=error:OSError` with `listeners: []` the whole time, but `tunnel-audit-fleet.sh` never read `ss_status`: the empty list compared as OK or GONE, and `--accept-baseline` froze it as the node's baseline, so the node's exposure audit saw no listeners at all (the actual node had 7 non-loopback listeners, 4 of them bound to 0.0.0.0/::). Now `tunnel-audit-fleet.sh` reports any node whose `tools.ss_status` is not `rc=0` as `DEGRADED <node>: listener scan unavailable (ss_status=…)`, exits 1 (owner notification), skips the comparison and refuses to accept that collection as a baseline. Collections from older collectors without `tools.ss_status` count as `rc=0`, so existing baselines compare as before. `tunnel-audit.sh` reads `ss -tlnp` with its header (no more `-H`) and requires the `State` header line: an ss that exits 0 with no output (or without `-H` support) is `error:ss-no-header` instead of "no listeners", and `--markdown` prints a `WARNING listeners unavailable` line. A header-only answer (genuinely nothing listening) is still trusted.
