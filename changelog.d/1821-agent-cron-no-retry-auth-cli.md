- **agent-cron no longer schedules a backoff retry for `auth_failed` / `cli_missing` failures (#1821).** A rejected credential or a missing/non-executable CLI fails the same way a minute later, so retrying only burned attempts (the 6-day silent auth outage in #1821 retried every run). `apply_retry_transition` now takes the run's `failureClass`; for those two classes it records `retryState` with `retryEligibleAt: null` and `lastStatus: "not-retryable"` (the store schema forbids extra keys, so every existing reader already treats it as "no retry pending" and `due` shows `retry-exhausted`), and the run result carries `retry.notRetryable`. `timeout` and `other` keep retrying as before, tasks without a `retryPolicy` still record nothing (#911), and the next regular schedule occurrence still runs. The consecutive-failure owner alarm from #2059 is unchanged.
