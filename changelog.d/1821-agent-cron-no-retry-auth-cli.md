- **agent-cron no longer schedules a backoff retry for a prompt task's `auth_failed` / `cli_missing` failure, and alerts the owner on that first failure instead (#1821).** A rejected credential or a missing/non-executable CLI fails the same way a minute later, so retrying only burned attempts. `apply_retry_transition` now takes the run's `failureClass`; for those two classes it records `retryState` with `retryEligibleAt: null` and `lastStatus: "not-retryable"` (the store schema forbids extra keys, so every existing reader already treats it as "no retry pending" and `due` shows `retry-exhausted`), and the run result carries `retry.notRetryable`. Because retries were what reached the consecutive-failure threshold within minutes, such a run now alerts at once (`threshold` 1 for that run; `failureAlertAfter: 0` still opts out and the `alertedClass` dedupe still applies) — otherwise a daily task would alert days later and a one-shot never. Command tasks keep retrying: their own stderr (a 401 from a restarting service) or a momentarily missing `cwd` also maps to those classes but is not proof of a permanent failure. `timeout` and `other` keep retrying as before, tasks without a `retryPolicy` still record nothing (#911), and the next regular occurrence of a recurring task still runs.
