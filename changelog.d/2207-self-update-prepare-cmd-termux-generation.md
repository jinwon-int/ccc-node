- **`ccc-self-update` gains an optional `prepare-cmd`, and Termux ships `scripts/termux-prepare-generation.sh` to build and point the prepared bridge generation automatically (#2207 ③).** On Termux the bridge runs from `~/.ccc-node/preparations/<gen>` behind the `bridge-current` symlink, so a fast-forward alone changed nothing: the restart re-launched the old generation and the tick ended `activation incomplete (serving-mismatch)` (two nodes sat weeks behind in October; the 2026-10-09 fleet update needed the same manual sequence again). `~/.claude/self-update.prepare-cmd` now runs after `setup.sh` and before any restart on a changed tick, with its own budget (`CCC_SELF_UPDATE_PREPARE_COMMAND_TIMEOUT_SECONDS`, 3600 s, max 7200) and `CCC_SELF_UPDATE_TARGET_SHA`/`PREVIOUS_SHA`/`REPO_DIR` in its environment; a failure skips every restart, records a `prepare-failed` pending activation with the exit code and budget, notifies, and exits 15, so the previous generation keeps serving. The Termux implementation is idempotent and fail-closed: already serving → no-op; a ready generation for the target → repoint only; otherwise `git worktree add --detach`, inherit `bridge/.env` (0600) from the serving generation, run `termux_prepare.py --verify-reinstall` reusing the serving generation's native wheels when `bridge/requirements.lock.txt` is unchanged (minutes instead of ~1 h), require a `ready` receipt, record the previous pointer and repoint. Nothing is deleted; `--dry-run`/`--status` are read-only. Install: `printf 'exec bash %s/ccc-node/scripts/termux-prepare-generation.sh\n' "$HOME" > ~/.claude/self-update.prepare-cmd`.
