- **SessionStart memory injection is bounded in characters, not only bytes (#2884).** Claude Code caps each hook output string at 10,000 characters and replaces a longer one with a file path and a ~2,000-character preview, so a block inside its byte budget could reach the session as its first fifth: 12,000 bytes is about 9,600 characters of mostly-Hangul memory but 12,000 of ASCII. Measured on the fleet, three nodes lost the block on every one of their last six sessions and two more on some. `load-memory.sh` now caps its output at `CCC_MEMORY_MAX_CHARS` (default 9500, 0 = off) next to `CCC_MEMORY_MAX_BYTES`; the cut falls on the tail, which is the lowest-priority block (the Wiki prefetch), and undecodable bytes are counted as the replacement characters they become. `nunchi/sessionstart.sh` passes `--max-chars` (`CCC_NUNCHI_INJECT_MAX_CHARS`, default 9500, 0 = off) to `nunchi.py assemble`: a block already inside the ceiling is printed unchanged; one that is over keeps 20% of the ceiling for facts (or what they need, if less), gives constraints the rest — still first — and counts the rows that do not fit in the existing `N건 생략` tail, which now names the bound that left them out. A constraint larger than the whole ceiling is left out and counted; no line is cut before the injection scanner runs. Characters are counted in UTF-16 code units, the cap's own unit. `scan-injection.sh` takes an optional third argument that re-applies a character cap after redaction, and `memory_render.py limit-bytes` an optional second one. Without `memory_render.py` the loader used to empty a block over the byte cap; it now keeps it, cut to the cap. The Codex/Piri materializer keeps the loader output it had (it sets the ceiling to 0; that path writes a file and is not a hook).
