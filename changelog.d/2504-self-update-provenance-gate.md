- **`ccc-self-update.sh` now gates every incoming commit on its GitHub author before the ff-merge (#2504).** The #1591 signature check cannot stop a merged external PR, because GitHub signs its own squash and merge-queue commits (cf. jinwon-int/a2a-nexus#2428). The gate makes one `gh api .../compare/OLD...NEW` call and requires each commit in `git rev-list OLD..NEW` to have a trusted `author.login` or an owner-approved SHA. The trusted logins are built in (`jinon86 seoseo-ai dependabot[bot] jinwon-deps-bot[bot] github-actions[bot]`); `~/.ccc-node/self-update-trusted-authors` replaces that list when present. Approved SHAs go in `~/.claude/state/self-update-approved-external-commits`. Neither list is ever read from the incoming checkout. `CCC_SELF_UPDATE_PROVENANCE_MODE=enforce` (default) notifies and exits 16 without moving HEAD; `warn` only reports; `off` skips the gate. If the lookup cannot complete (no `gh`/`jq`, API failure, non-GitHub remote, truncated compare, malformed JSON), `CCC_SELF_UPDATE_PROVENANCE_ON_ERROR=hold` (default; `proceed` under `warn`) exits 16 and alerts after `CCC_SELF_UPDATE_PROVENANCE_FAIL_ALERT_AFTER` (2) consecutive holds. Up-to-date ticks never call `gh`. Nodes need an authenticated `gh` for the cron account.
