- **agent-cron now pushes one owner alarm when no prompt task has succeeded for 7 days (#1821 proposal 1).** The consecutive-failure counters need three failures in a row, so a sparse (e.g. weekly) prompt task could fail for weeks before alerting, and until now only `ccc-doctor` warned about the stale window. A failing prompt run now raises a `node=stale` alarm when the newest prompt success — or, with none recorded, the oldest recorded prompt run — is more than `CCC_AGENT_CRON_PROMPT_STALE_DAYS` days old — the same strict boundary as the ccc-doctor check (default 7, `0` disables; tasks with `failureAlertAfter: 0` and `CCC_AGENT_CRON_FAILURE_ALERT_AFTER=0` stay excluded). It fires once per stale stretch (`staleAlertedAt` in `failure-alarm.json`) and re-arms on any later prompt success; it merges into the same single message when another alarm fires on that run. It cannot fire while no prompt run is attempted at all — the doctor check still covers a node whose scheduler simply stopped. Health-file wiring (proposal 3) is out of scope: `health.json` is rewritten whole from the bridge process's in-memory state, so another process cannot safely write into it.
