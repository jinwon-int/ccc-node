- **Weekly fleet span summary on a Family Wiki page (#2899).** `scripts/spans-weekly.py` folds the hub's daily span-view records (`<state>/spans-view/data/<day>/<node>.json`, `_status.json`) for the previous Monday–Sunday (KST) into one Markdown section — per-node table (days collected n/7, turns, tool calls, tool error rate, cost USD, largest daily cost-ledger difference, a2a ok/failed when any node reported it), a fleet total, the five tools with the most errors, "big changes" against the week before (tool error rate +2 %p, or turns per collected day ≤0.5× / ≥2× — provisional, `--error-rate-pp` / `--turns-low` / `--turns-high` or `CCC_SPANS_WEEKLY_*`) and the days not collected with their reason codes. A week with no collected day is one 「수집 없음」 line. It opens no connection to any node and writes numbers and identifier-shaped tool names only (anything else in a name becomes `?`). The section goes to `pages/services/span-rollup.md` through `wiki-agent write-path` → edit → `wiki-agent pr`: each section carries `<!-- span-weekly:YYYY-Www -->` and a week already on the page or in its yearly archive is never written again; the page keeps the newest 12 weeks with a digest line for the newest one at the top, older weeks move to `span-rollup-archive-<year>.md`; `--catch-up 1` (default) re-adds a week whose PR failed on the next run. `--dry-run` prints the Markdown only. `scripts/install-spans-weekly-timer.sh` prints (dry-run) or installs (`--apply`) a Monday 05:00 Asia/Seoul timer on the hub. The nightly rollup's `metrics/span-rollup` wiki-candidate now suggests `pages/services/span-rollup.md` instead of `pages/fleet/span-rollup.md`.
