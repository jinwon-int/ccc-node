- **`approve-via-relay.sh --base NAME` reviews PRs into a promotion branch (#2492).** The relay approval helper accepted only PRs into the repository's default branch, so a promotion PR (#2292, e.g. wiki-agent `promote/... -> stable`) that the `protected-branch-NAME` ruleset requires a cross-account approval for had no approval path (observed on wiki-agent#223). With `--base NAME` the helper accepts the PR only when its base is `NAME` and the branch's applied rules include deletion, non_fast_forward and a pull_request rule requiring at least one approval (unreadable rules fail closed), and reads the required checks from `NAME`. `master`/`main` (any case) and non-plain names are refused locally, `NAME` equal to the default branch is refused remotely, and without `--base` the default-branch check is unchanged. The result JSON gains `promotion`. Exact-head checks are still required, so the target repository's CI must run on PRs into the promotion branch.
